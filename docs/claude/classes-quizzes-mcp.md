# Instructor classes, quizzes and the MCP server

Moved verbatim from CLAUDE.md on 2026-11-20. Keep it current when the code changes.

**Instructor classes** (`lib/classes.ts`, free): a signed-in teacher makes a class for any test on the site at `/teach/new` (a searchable picker over `TEST_GROUPS`: the DMV with a required state, stored as examId `dmv` plus the class's `state`; a v1 registry exam or its state version; or a v2 exam, by its own id; `classExamInfo()` resolves name, home, pass mark and topic labels for all three) and posts its link, `tigertest.io/c/<code>` (5 characters, no 0/O/1/I/L). A student types the name their instructor knows them by on `/c/<code>` (no account) and lands on the exam dashboard, which shows a `ClassBanner` saying their scores are shared, with Leave. Memberships (class and quiz) live in localStorage (`tigertest-classes`); its random `memberId` is both the member doc id and the secret that lets only its holder report for that student. While signed in that list is a copy of `users/{uid}.classMemberships` (`lib/classMembershipSync.ts`, `components/ClassMembershipSync.tsx` in the root layout): joins and leaves update the account in a transaction, a guest's memberships are added to the account on sign-in, another device loads the account's list (same memberId, so it reports to the same student row), and sign-out clears the browser's copy (`tigertest-classes-uid` records which account it belongs to). `lib/classProgress.ts` queues every answer on `ExamTestPage`, `ExamTrainingPage`, the DMV `app/test/[id]` and `app/training` pages and the v2 `DrillRunner` (a finished v2 `ExamRunner` test reports every item at submit) (question, category, right or wrong) and every finished practice test, and flushes to `/api/classes/[code]/progress` every 5 seconds and on page hide. Firestore: `classes/{code}` (teacherUid, examId, memberCount) and `classes/{code}/members/{memberId}` (answered, correct, byCategory, missed and seen per question, `picks` per question (wrong answers by the option's bank index, recorded since Oct 19 2026; v1 carries the shuffle as `Question.optionOrder`, v2 reports single-choice items only), tests by number with best and attempts). The teacher's `/teach/classes/[code]` reads `/api/classes/[code]/report` (owner or site admin, `lib/server/classAuth.ts`), built by `lib/server/classReport.ts`: totals, topics weakest first, every question the class answered as the /stats `QuizRow` (most missed or lowest accuracy, tap for the options with the right answer marked and each wrong option's pick count, the class counts and the explanation; `components/teach/ClassQuestions.tsx`), and one row per student. The class page's share pieces are `components/teach/ClassShare.tsx`: Copy message for students (a ready-to-paste line with the full link, British spelling for en-GB), Copy link, and Show QR code (full screen, for the classroom board; Escape closes). An empty class shows the message and the same buttons in its No students yet card. The teacher edits a class's name, their own name and the school from that page (the pencil by the name or "Edit details", `components/teach/ClassDetailsForm.tsx`; `PATCH /api/classes/[code]` with any of `name`, `teacherName`, `school`, owner or admin, which also updates `className` and `classTeacherName` on the class's quizzes; an empty school clears it; the exam cannot change, since progress is stored against it; students who already joined keep the old name in their local `ClassBanner` copy). The /teach class list shows each class's school. The teacher deletes a class from the bottom of that page (`components/teach/DeleteClassButton.tsx`, a confirm, then `DELETE /api/classes/[code]`, owner or admin): the class doc and every member doc go (`recursiveDelete`), and its class quizzes become `private`; a student's next progress report gets 410 from `/api/classes/[code]/progress`, and `flushClassProgress()` drops that membership with `leaveClass()`, so the banner goes. A DMV class sets a new student's state on join; a student already on another state chooses to switch (resetting DMV progress, as Settings warns) or keep theirs. Before Oct 19 2026 a progress batch with no wrong answers wiped the member's `missed` and `picks` maps (an empty map in a merge write replaces the stored one); `components/exam/ClassMissRecovery.tsx` (v1 and DMV dashboards and training pages) sends each joined browser's own answer history once per class to `/api/classes/[code]/recover`, which rebuilds `missed` from answers since `joinedAt`, keeping the higher count. Wrong picks from before then cannot be recovered. Question text for the class page comes from `lib/server/classQuestions.ts`, which loads the DMV, v1 and v2 banks. `/teach` is the indexed instructor landing (`components/teach/TeachLanding.tsx`, hero animation `components/stageshow/demos/TeachClassDemo.tsx`) and the class list once a teacher has classes. **Language**: every teacher page (the /teach landing and its hero animation, the class list and quizzes, `/teach/new`, a class page and its share, edit, delete, questions and student pieces) shows in the person's interface language. All copy lives in `components/teach/teachCopy.ts` (English and en-GB, plus the `TeachCopy` type, phrase functions for plurals and word order) and `components/teach/copy/<lang>.ts` for the other sixteen (machine-translated, final; `TRANSLATED_TEACH_COPY` must have every language, so a new interface language fails typecheck until it gets a file); components read it with `useTeachCopy()`. The server render is English (crawlers carry no language cookie), so the indexed landing and its FAQ JSON-LD stay English. Test names and catalog group titles stay as `lib/testCatalog.ts` has them. `ClassQuestions` and `StudentDetail` take `audience="quiz"` on the quiz report, which is still English-only. `tests/teach-copy.test.cjs` checks every language. It replaced the driving-school program: `/schools/*` redirects to `/teach` in `next.config.ts`, the footer links "For teachers" everywhere, and the old school pages are gone (the `/api/schools` routes and `school_accounts` data remain, unused). Not yet: Basics questions, the v1 drill page, progress from a second device for a student without an account, and teacher email digests.

**Quizzes** (`lib/quizzes.ts`, free): anyone with an account turns their own material into a Tigertest practice test, played at `tigertest.io/q/<code>` (6 characters, the class-code alphabet, so never mistaken for a class code) in three modes, Practice (the v1 mastery engine with the wrong-answer queue; `toEngineQuestion()` maps a quiz question onto `Question` with state `QUIZ` and id `<code>-q<n>`), Test (every question once, pass mark `passPct`, default 80) and Flashcards, and shared by link. Tigertest never pays for a model call to write a quiz: there is no server-side generation (the paste box that ran on our key was removed on day one). Quizzes are made through the person's connected Claude or ChatGPT: `/create` is one public page with the connector setup (Add it to Claude / ChatGPT, `#add-to-claude` and `#add-to-chatgpt`), Just ask, the FAQ and, once signed in, Your quizzes and Recently played (`CreateYourQuizzes`); `/connect` permanently redirects there. The assistant writes questions using `QUIZ_WRITING_GUIDE` from `lib/quizWritingGuide.ts` (the `get_quiz_writing_guide` tool and `write_quiz` prompt), then calls `create_quiz` to save them. There is no copied-prompt/JSON-reply workflow. Existing quizzes retain the owner editor; import helpers remain internal, not a creation workflow. Files: `lib/quizzes.ts` (types, `QUIZ_LIMITS`, validators, `quizUrl`/`quizPath`, `quizSummary`, `quizPublic`), `lib/server/quizzes.ts` (`createQuiz`, `updateQuiz` with `addQuestions`, `deleteQuiz`, `listMyQuizzes`, `listPublicQuizzes`, `getQuiz`, `setQuizFeatured`, `isPremiumUid`, `QuizError` with `.status`, `bumpCounter`, `quizAsClassDoc`, `quizReportSubject`), `lib/server/quizAuth.ts`, `lib/server/classMembers.ts` (the member-doc batch apply shared by classes and quizzes), `store/useQuizStore.ts` (localStorage `tigertest-quizzes`, mirrored to `users/{uid}.quizProgress` by `components/quiz/QuizSync.tsx` through `lib/quizSync.ts`, like the v2 store), `lib/quizProgress.ts` (join, plays) and `lib/quizClient.ts`; API routes `app/api/quizzes/` (`POST`/`GET` the account's own, `public`, `[code]` GET/PATCH/DELETE, `[code]/join`, `play`, `progress`, `report`, `report-question`); pages `app/q/[code]/{,dashboard,practice,test,test/results,flashcards,report,edit}` (the root is the share landing using the same `LandingIntro` as exam landing heroes; `/dashboard` holds personal modes/progress and named play), `/create` (setup and your quizzes), `/quizzes` (the public library), components in `components/quiz/`. Every quiz renders through these shared components, so a change to them reaches every quiz, old and new. The quiz dashboard (`QuizHome`) is laid out like the exam dashboards and shares `ProgressCard`, but its hero is its own code: when a change to the exam dashboard heroes should apply to quizzes, make it in `QuizHome` too. The footer is the short one on quiz pages (`isQuizPage` in `components/Footer.tsx`). Firestore: `quizzes/{code}` (`QuizDoc`: ownerUid, ownerName, visibility `private`/`link`/`public`/`class` (with `classCode`, `className`, `classTeacherName` while `class`), passPct, questions with stable ids `q1..qN` never reused after a delete, createdVia `web`/`import`/`mcp`, plays, memberCount, reports, nextQuestionId, `featured`), `quizzes/{code}/members/{memberId}` (the class member shape), `quizReports` (bad-question reports, also counted on the quiz), `analytics/quizzes` (counters `created_web`, `created_import`, `created_mcp`, `plays`, `questionReports`, in the Quizzes tab's footnote) and `users/{uid}.quizProgress`. Limits (`QUIZ_LIMITS`): free 3 quizzes of 50 questions, Premium 100 of 200; at least 3 questions, exactly 4 options. `publicRank` holds `plays` only while a quiz is public (deleted otherwise), so the library and sitemap order public quizzes with one single-field `orderBy`; `listPublicQuizzes` lists public quizzes with `QUIZ_PUBLIC_MIN_PLAYS` (5) plays, featured ones first and before 5 plays; the `/quizzes` library (page and `/api/quizzes/public`) passes `minPlays` 0 so every public quiz is listed, while the sitemap, `quiz_me` search and the quiz page's index tag keep the 5-play floor (`featured` is admin only, `PATCH /api/quizzes/[code]` with `{featured}`; `data/quizzes/*.json` are seed quizzes that `npx tsx scripts/seed-quiz.ts` loads for an account by email, `--featured`). A player who gives a name on the quiz page becomes a member (`joinQuiz()` in `lib/quizProgress.ts`, membership kind `quiz` in the `tigertest-classes` localStorage list), and `lib/classProgress.ts` reports their answers under examId `quiz:<code>` (`quizExamId()`) to `/api/quizzes/[code]/progress`; anonymous play only counts in `plays` (once per browser via `/api/quizzes/[code]/play`). The creator's `/q/<code>/report` is `buildClassReport()` over the quiz's members with `quizAsClassDoc()` and `quizReportSubject()` (topics are the questions' free-text `topic` labels). **Who can play** is three choices on the edit page (`QuizEditor`): Everyone (`link`, or `public` with "Also list it in the Tigertest library" ticked), Only me (`private`), and My class (`class`: one of the owner's /teach classes, checked as theirs by `classFields()` in `lib/server/quizzes.ts`; with one class it is picked for them). A class quiz is enforced on the server by `quizAccess()` in `lib/server/quizAccess.ts`: owner or admin, else a browser that sends its class membership (`CODE:memberId` from `tigertest-classes`, header `x-tigertest-classes`, added by `loadQuiz()`) for that class, checked against `classes/{code}/members/{memberId}`; `/api/quizzes/[code]` answers anyone else 403 `classOnly` with only the title and teacher name, `/q/<code>` never server-renders it, and `[code]/join` needs `classMemberId`. A non-member sees `ClassQuizGate` in `QuizLoader` (class code plus name), which posts `/api/quizzes/[code]/class-join`: it joins only the quiz's own class (via `joinClassMember()` in `lib/server/classMembers.ts`, shared with the class link) and never reveals the code. A student already in the class goes straight in and is joined to the quiz under their class name (`autoJoinClassQuiz()` in `lib/quizProgress.ts`), so the quiz report lists them. Assistants cannot play someone else's class quiz (`QUIZ_CLASS_ONLY`). MCP tools (`lib/server/mcp-tools.ts`): `get_quiz_writing_guide`, `create_quiz` and `update_quiz` (visibility `class` with `classCode`; `CLASS_REQUIRED` returns the classes to ask about, `NO_CLASSES` the /teach/new link), `list_my_classes`, `add_quiz_questions`, `list_my_quizzes`, `get_quiz` (answers only for the owner), `delete_quiz` (confirm required), `get_quiz_report`, plus the `write_quiz` prompt. Launch email: `quizzesLaunch` in `lib/email-templates.ts`, sent by `/api/cron/quizzes-launch` (13:30 UTC, key `quizzesLaunch2026`, whole consented base, accounts 7+ days old and active within a year) only while `QUIZZES_CAMPAIGN=send`; paused it logs the eligible count. SEO: `/create` and `/q/<code>` pages are crawlable, and the `quizzes` sitemap segment (`lib/sitemaps.ts`) lists `/quizzes`, `/create` and every public quiz from `listPublicQuizzes(500)` (empty without a Firestore credential), dated `QUIZZES_PAGES_UPDATED_AT` in `lib/seoDates.ts`; `lib/llmsTxt.ts` has a quizzes section. The footer Make a quiz link opens /create.

**MCP server** (`app/api/mcp/route.ts`, Streamable HTTP, stateless, 60 requests a minute per uid): Claude, ChatGPT and any MCP client sign in with OAuth 2.1 + PKCE bridged to Firebase Auth (`app/api/mcp/oauth/*` for register, authorize, callback and token; discovery at `app/.well-known/oauth-authorization-server` plus the RFC 9728 protected-resource metadata at `app/.well-known/oauth-protected-resource` (and its `/api/mcp` path-suffixed twin, both from `lib/server/mcpResourceMetadata.ts`), which the 401 from `/api/mcp` points at with a `resource_metadata` hint so clients start OAuth on their own; the consent page `app/oauth/login` can also create the account, since connecting from a chat is many people's first contact; someone already signed in is shown the client name, their account and where they will be sent, and must press Allow, never authorized by the link alone; `lib/oauthRedirect.ts` limits registered redirect URIs to https, http on loopback, or an app's own scheme, checked at register and again before a code is issued), and `lib/server/mcp-auth.ts` mints HS256 JWTs signed with `MCP_TOKEN_SECRET` and issued by `MCP_OAUTH_ISSUER_URL` (the public site URL, also used for the links tools return). Tools live in `lib/server/mcp-tools.ts` (`ToolEntry` objects pushed onto `tools`, zod input shapes, `ok()`/`fail()` from `lib/server/mcp-tool-helpers.ts`, `userId` only ever from `ctx`): the two-call quiz loop any agent can run with no state of its own (`quiz_me` takes a quiz code, `"dmv"` or search words and returns one question; `answer` grades a letter and returns the explanation, progress and the next question; `find_quiz` searches the person's quizzes and the public library; `reset_quiz_play` starts over), backed by `lib/server/mcpQuizPlay.ts` (mastery queue per account and quiz in `mcpQuizPlay/{uid}_{code}`, the same fresh-first then wrong-queue rule as the site, a play counted on the first answer, and a named member `u_<uid>` with `via: "assistant"` on someone else's quiz so the creator's report shows assistant play; `"dmv"` wraps the training-set tools on the first unmastered set), the DMV tutor tools over `lib/server/progress.ts` (state, progress, training sets, practice tests, weak areas) and the quiz authoring tools above. `/create` is the setup page people follow to add the connector, `/developers` is the page for builders and the directory submissions (endpoint, auth, tool list, example prompts, icon, privacy, `/terms`), and `MCP_SERVER_PLAN.md` and `MCP_TESTING.md` are the spec and the test notes.

**MCP study continuation**: `list_in_progress_tests` discovers only the caller’s synced account progress (site started-test signals, plus learned Basics/custom quiz history). `get_study_progress`, `start_study_practice`, and `submit_study_answer` add v1 registry and v2 drill practice without replacing legacy DMV or custom-quiz tools. Catalog practice updates `users/{uid}.trainingSets`/history; v2 uses its existing drills and grader. Pending attempt IDs prevent stale answer replay. Timed/adaptive sittings remain web-only and unchanged. Browser sync is not live collaboration. MCP writes increment per-store mcpProgressRevisions (catalog/v2/quiz); browser save transactions reject stale revisions and latch a visible conflict until explicit reload. This preserves newer cloud progress without guessing reset/delete merge intent; unsynced browser work may need repeating. Scope baselines are captured before local replacement, never refreshed mid-session. No model calls.
