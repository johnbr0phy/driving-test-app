# SEO conventions

Moved verbatim from CLAUDE.md on 2026-11-20. Keep it current when the code changes.

### SEO conventions

- **More than one indexable page per exam (Nov 10 2026).** Besides its landing, an exam can have: (1) **state landings** for the 42 state versions of real estate, life and health and P&C at `<family landing>/<state-name>` (`/real-estate-practice-test/california`; `lib/stateLandings.ts`, `components/exam/StateExamLanding.tsx`, three `[state]` routes), built from the variant's `ExamConfig`, its bank and `lib/stateExamFacts.json`, which `python3 -I tools/build_state_exam_facts.py` generates from the "Official exam facts" table of each `docs/*-state-sources/*.md` (CI runs `--check`; rows over 200 characters stay in the notes); a new variant gets its page automatically. (2) **Topic pages** `/questions/<exam slug>/<topic>` for the v1 exams in `TOPIC_EXAM_IDS` (`lib/topicPages.ts`, one route `app/questions/[exam]/[topic]`): ten bank questions of one category with answers, a topic needing 5 questions (`perTest x testCount`); `TOPIC_TITLES` gives a page the search phrase as its title (CDL endorsements "CDL HazMat Endorsement Practice Test", civics "US Citizenship Test Questions: <topic>") and `TOPIC_ALSO` lists another exam's pages on a landing (the CDL landing lists the endorsements). v2 exams in `TOPIC_V2_EXAM_IDS` (`lib/v2/topicPages.ts`, Nov 14 2026: ASVAB, TEAS, HESI, GED, SAT, ACT, NCLEX-RN, NCLEX-PN, EMT) get one page per drill on the same route, plus the ASVAB's `/questions/asvab/afqt` across its four AFQT subtests: ten printable questions (`lib/v2/printable.ts`: single answer, no figure or table, short passages allowed, never a held-out test), titled "<exam> <drill> Practice Test", linked from the landing through `ExamRelatedTests` (and the ASVAB landing's subtest rows); `SKIP` drops drills with under five printable questions (ACT reading and science, two NCLEX areas), which `tests/topic-pages-v2.test.cjs` checks. (3) **Most-missed pages** `/questions/<exam>/most-missed`: the top 5 Common Mistakes with miss rates from `globalStats/examWrongQuestions` (`lib/server/mostMissed.ts`), rendered on first request and revalidated daily, 404 until the exam has the data; the rest of the list stays the Premium tab. (4) **Teacher pages** `/teach/<exam slug>` for every English exam in the `TEACHES` map of `ExamClassFaq` (`lib/teachPages.ts`), whose button opens `/teach/new?exam=<id>`; the class FAQ on each landing links to it. All four are in the `exams` sitemap segment and llms.txt, and landings link to the first two through `ExamRelatedTests` (`ExamTopicLinks`, plus `ExamLanguageLinks` to the same test's other-language landings).
- **Search phrasing for the biggest pools (Nov 14 2026).** A DMV state page takes its title, description, H1 and extra FAQ from an optional `seo` block in `data/stateLandingData.ts` (California "ca permit test", New York "ny permit practice test", Georgia "dds practice test"); facts in it come from `data/states.ts` only. The healthcare entry landings (TEAS, HESI A2, CNA, NCLEX-RN, NCLEX-PN, PTCB, EMT) carry `components/exam/ExamPriceFaq.tsx` and its `priceFaqJsonLd()`: free to start, one Premium payment at the US list price (local elsewhere), against paid prep that "often costs $100 or more", no competitor named.
- **Sample questions on every landing.** v1 landings render `<ExamSampleQuestions examId>` (import the bank first), v2 landings `<SampleQuestionsV2 examId>` (`components/v2/SampleQuestionsV2.tsx`: one standalone single-answer question per domain, never from a held-out test), DMV state pages `DmvSampleQuestions` with that state's own questions. Add the two lines to a new landing.
- **Offers and exam costs.** A landing's `WebApplication.offers` is `examOffers(examId, currency?)` (`lib/examSeo.ts`): free practice, plus the Premium price in that currency when the exam has Premium steps. Never write `price: "0"` by hand. `lib/examCosts.json` holds the real exam's fee and retake rule for about 30 exams, each read on the official body's own page (URL kept beside it, `checked` date); `ExamFacts` shows them with an "official source" link and llms-full.txt carries them. Only add a figure read on the official site, and re-check the file when a fee changes (NCLEX rises Feb 1 2027; FINRA and NASAA retake waits change in Jan 2027).
- **Revenue attribution.** Every checkout sends the browser's first-visit `source` and `landing` (`checkoutAttribution()` in `lib/funnel.ts`, falling back to `signupOrigins/{uid}` on the server); the webhook stores both on the `payments` doc, the Today tab shows revenue by source and by landing page, and the GA4 `purchase` event carries `first_source` and `first_landing`. Checkout no longer forces `payment_method_types: ['card']`, so Stripe offers the methods enabled in the dashboard for the buyer's country.
- **Try one now (Nov 15 2026).** `ExamLandingHero` is a server wrapper (`components/exam/ExamLandingHero.tsx`) over the client hero (`ExamLandingHeroClient.tsx`): it picks one question from training set 1 (part 1 when split) of the bank the page imported (`pickLandingTryQuestion()` in `lib/landingTryQuestion.ts`; sign-image and "A and B" items skipped) and shows it playable under the Start button (`components/exam/LandingTryQuestion.tsx`). The answer starts a guest session, is recorded in set 1 with `answerTrainingSetQuestion` (so it counts as the funnel's first answer) and "Keep going" opens that set. v2 landings (Nov 19 2026) take the easiest plain-text single-answer question (no KaTeX, tables, passages or markup; number options sorted) from their first free drill that has one, record the answer in that drill (`answerDrill`) and "Keep going" opens its questions (Nov 20 2026: exams with no plain-text question, such as SAT, PSAT, ACT, GRE, LSAT, CogAT, the AP language and calculus exams and the reading tests, fall back to one with bold, line breaks or KaTeX, then to one on a short text passage; `rich: true` makes the server hero draw it with `RichTextStatic` from `components/v2/richTextNodes.tsx`, so KaTeX never ships to the browser and its CSS comes from the page's `SampleQuestionsV2`. Every v2 landing now has a card; `tests/landing-try-question.test.cjs` keeps it that way). A page that imports no bank and state-version landings (`tryQuestion={false}`) show no card. It ran as an A/B test (`landingTry1`, Nov 15 to 19 2026): new visitors who saw it answered a first question 55% of the time against 45% without (+10 points, p = 0.001), with sign-ups not lower, so it now shows to everyone in place of the screenshots and the test code is gone.
- **Homepage catalog is server-rendered.** `components/TestCatalogStatic.tsx` and `components/TestCard.tsx` (no "use client") render the homepage's cards as plain HTML; only the country pills hydrate. `/tests` keeps the client `TestCatalogGrid`; keep the two groupings in step.

- **One host: www.** Vercel sends `tigertest.io` to `www.tigertest.io`, so every canonical, sitemap, hreflang, JSON-LD, llms.txt and IndexNow URL is built on `SITE_URL` from `lib/siteUrl.ts` (it lifts an apex `NEXT_PUBLIC_SITE_URL` to www). Never write `process.env.NEXT_PUBLIC_SITE_URL || "https://tigertest.io"` in a page again; import `SITE_URL`.
- **Page language.** The one root layout serves `<html lang="en">`; pages under `/es`, `/pt`, `/vi`, `/ko`, `/zh`, `/de`, `/nl` and `/fr` (with the Nordic, Hungarian, Romanian and Greek prefixes) get a `Content-Language` header and `<html lang>` set before first paint from `lib/urlLanguage.ts` (next.config.ts headers and `URL_LANG_INIT_SCRIPT`), and `LanguageContext` keeps a URL's language on its pages.
- **Dates and counts per exam.** A landing's `dateModified`, visible "Updated" line and sitemap `lastmod` come from `lib/landingDates.json` (`npx tsx scripts/build-landing-dates.ts`, git dates of each exam's landing, bank and landing JSON; rerun after committing a landing or bank change, `--check` reports staleness). The catalog's question count is the bank size from `lib/examBankSizes.json`, written by `scripts/build-training-parts.ts`. A DMV state's pass mark is its exact `passCount` in `data/states.ts` (the percent is derived).
- **/about** (`app/about/page.tsx`) says who makes Tigertest, how questions are written, the price and independence; it is linked from the footer and llms.txt and is the Organization's `AboutPage`. The Organization node (`lib/siteSchema.ts`) builds its description from the catalog and `REGIONS`.
- **Country homepages** outside the US carry their own h1 (visually hidden: the top of every homepage shows the same tagline and weekly count as the US page) and lead from `regionHeadline()` (`lib/regionHeadline.ts`, built from the region's hub groups) and region-filtered trending searches.
- **Landing pages** (`app/<x>-practice-test/page.tsx`) are the only exam URLs meant to rank. Each sets its own metadata (title, description, canonical, Open Graph image at `/og/<examId>` from `app/og/[examId]/route.tsx`) and a `WebApplication` + `FAQPage` JSON-LD graph (no breadcrumb: removed Oct 2026, the crumb pushed the headline down and Google no longer shows trails on mobile), and renders `<ExamRelatedTests examId>` before the final CTA (cross-links within the exam's hub group from `relatedTests()` in `lib/testCatalog.ts`). Write metadata and JSON-LD strings with plain apostrophes; `&apos;` only belongs in JSX text.
- **App routes** (`app/<slug>/layout.tsx`) export `examAppMetadata(id)` from `lib/examSeo.ts`: the exam's own title and `noindex, follow`. They are deliberately not disallowed in `app/robots.ts` so crawlers can read the tag. DMV app routes keep their robots.txt disallow.
- **GEO (AI answer engines)**: every exam landing renders `<ExamFacts examId>` under the hero: a plain answer about the real exam, a facts table and a dated "based on" line with the official source, plus a `WebPage` node with `dateModified` (`EXAM_LANDINGS_UPDATED_AT`). The facts live in `lib/examFacts.ts`; keep them in step with the landing's FAQ and add an entry with each new exam. `/llms.txt` and `/llms-full.txt` are generated from the catalog, exam facts and state data (`lib/llmsTxt.ts`, DMV first, with the 51-state written-test table). The site-wide `Organization` and `WebSite` nodes are in `lib/siteSchema.ts`, rendered once by `app/layout.tsx`; point new JSON-LD at them by `@id`. `app/robots.ts` gives every crawler, AI or not, the same allow/disallow lists. First visits are counted by source (`visitSource()` in `lib/funnel.ts`: ChatGPT, Perplexity, Gemini, Copilot, Claude, search, direct, other), shown on the Growth tab, where each engine and search have their own line (search on its own axis) and a source whose last 7 days fall 30% or more under its usual week is flagged. DMV state pages are deliberately left as they are.
- **Sample questions** (`components/exam/ExamSampleQuestions.tsx`): the 29 non-US driving test landings show six bank questions (the last of each category in ID order, sign-image and "A and B" items skipped, options rotated so keys spread over A to D) with answers and explanations in plain HTML plus a `Quiz` JSON-LD node, for "<test> questions and answers" searches and AI answers. The page imports its own bank (`import "@/lib/banks/<id>"`), so nothing else bundles it; add both lines to a new country's landing. `ExamRelatedTests` links a country's exam up to its country homepage, and country homepages list each local test's `EXAM_FACTS` answer under "About each test". `/llms.txt` has a generated "Practice tests by country" section (`countrySection()` in `lib/llmsTxt.ts`).
- **IndexNow** tells Bing, which ChatGPT search reads, about changed pages. After every production deploy, `.github/workflows/indexnow.yml` (on Vercel's `deployment_status`, also runnable by hand with a `days` input) runs `scripts/indexnow-recent.mjs`, which reads the live sitemap and sends every URL whose `lastmod` is within 2 days, using the public key; no secrets. So a launch reaches Bing within minutes, as long as its `lib/landingDates.json` or `lib/seoDates.ts` date was bumped. The nightly cron calls `/api/indexnow/ping?days=2` (`lib/indexNow.ts`); without `days` the route sends every sitemap URL (Nov 2026: before this, launches waited up to a day for the nightly full resubmit). Both senders record each run (`lib/indexNowSent.mjs`: `indexNow/sent` keeps first and last send per page path and each sender's latest run, `indexNowRuns` one doc per submission); the deploy workflow installs firebase-admin and uses the `FIREBASE_SERVICE_ACCOUNT_KEY` secret only for that, and a failed write never fails the send. "Sent" means Bing accepted the list, not that a page is indexed. The key file is served at the host root, `/<key>.txt` (a rewrite in `next.config.ts` to `/api/indexnow/key`), because a key file's folder limits which URLs it may submit.
- **Footer** internal links appear on landing pages only and stay inside the test's cluster (`relatedTests` on an exam landing, popular states on DMV landing and state pages); every footer links the `/tests` hub, never all the exams.
- **Sitemap** is an index (`app/sitemap.xml/route.ts`) over per-family files in `app/sitemaps/[segment]/route.ts` (`dmv`, `dmv-es-vi-ko` (which also holds the Chinese pages; the name is kept so Search Console keeps its history), `exams`; `/teach` is in `exams`) built by `lib/sitemaps.ts`, so Search Console shows DMV coverage separately. `lastmod` comes from the hand-bumped dates in `lib/seoDates.ts`; bump the relevant constant when a page family's content changes.
